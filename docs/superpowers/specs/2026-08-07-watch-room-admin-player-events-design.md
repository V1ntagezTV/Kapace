# Синхронизация нативных событий администратора

## Цель

Нативные Play/Pause/Seek в YouTube-плеере владельца или модератора должны обновлять
общее состояние комнаты через SignalR. Нативные действия обычного участника остаются
локальными.

## События плеера

`YouTubePlayerAdapter` публикует изменения состояния IFrame API: `playing`, `paused`
и `buffering`. У YouTube IFrame API нет отдельного события seek, поэтому перемотка
определяется периодическим сравнением фактической и ожидаемой позиции.

## Поведение по ролям

- Owner/mod: нативный Play вызывает Hub `Play`, Pause вызывает `Pause`, а скачок
  позиции более 1,5 секунды после короткой стабилизации вызывает `Seek`.
- Обычный участник: нативное расхождение переводит клиент в `local` без Hub-вызова.
- Пользователь в `local` не применяет общие события owner/mod автоматически и
  возвращается к комнате только кнопкой «Синхронизироваться».

## Анти-эхо и конкурентность

Событие, уже совпадающее с актуальным `PlaybackSnapshot`, игнорируется. Программные
изменения при применении snapshot не отправляются обратно в Hub. Нативные команды
owner/mod сериализуются; повторные события во время активного вызова объединяются.
Состояние комнаты изменяется только после подтверждённого `PlaybackStateChanged`.

При ошибке Hub локальный плеер администратора переводится в `local`, а ошибка
показывается через существующий toast.

## UI и проверка

Существующая панель «Управление всей комнатой» сохраняется. Сразу под iframe
показывается компактный индикатор текущего режима:

- красная точка и подпись `LIVE` — клиент синхронизирован с комнатой;
- серая точка и подпись `OFFLINE` — клиент находится в локальном просмотре.

Индикатор получает текстовое описание для screen reader и не использует один цвет
как единственный способ передачи состояния.

Проверка выполняется через `npm run lint`, `npm run build` и вручную в двух браузерах:

1. Нативные Play/Pause/Seek owner/mod применяются у синхронизированного участника.
2. Нативные действия viewer не изменяют комнату.
3. Viewer в `local` не сбрасывается событием администратора.
4. Программное применение snapshot не создаёт цикл Hub-вызовов.
5. Индикатор меняется между `LIVE` и `OFFLINE` при входе и выходе из local-режима.
